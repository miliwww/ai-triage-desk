# 字段字典与关联说明

通用约定：JSON对象的`id`是稳定字符串主键；数组顺序不表示优先级。`*_id`表示外键；`*_ids`表示外键数组。完整递归字段类型以`schema/*.schema.json`为准，数据文件与Schema对应关系见`schema/contracts.json`。

`null`表示未知、未核实或尚无结果；不能当作0、false或已完成。`is_synthetic=true`表示该记录是虚构的。公共产品资料不使用“整条虚构”标记，而使用`fact_status`和`field_provenance`说明真假边界。

## 1. 工单 seed/tickets.json

| 字段 | 类型 | 含义/注意事项 |
| --- | --- | --- |
| id | string | 工单主键，如WO-0001 |
| external_reference | string | 虚构的来件引用，不是官方编号格式 |
| title | string | 面向客服的中文标题，含整理后的问题线索；不能作为盲测模型输入 |
| customer_id / tenant_id | string | 服务客户及权限租户；读取前必须匹配当前用户权限 |
| site_id / device_id / product_id | string | 站点、设备实例、产品参考；产品不是具体某台设备 |
| country_code / language | string | 设备所在国家、来件主要语言；不是根据客户国籍推断 |
| channel | enum | online_service_center / email / phone_transcript / installer_portal / app_feedback |
| created_at / updated_at | UTC string | 接收时间、最近状态事件时间 |
| reported.serial_number | string/null | 客户明确提供的SN；可与已授权的device_id档案分开 |
| reported.model | string/null | 客户报告的型号；发生冲突应人工核对，不静默覆盖 |
| reported.occurred_at | UTC string/null | 客户报告发生时间；缺失时不得从接收时间冒充得出 |
| reported.symptom_description | string | 客户原文，保留原语言及已提供信息 |
| reported.error_code_literal | string/null | 原样记录的演示未知代码，未赋予真实故障含义 |
| reported.purchase_proof | null/object | 此版保修咨询均没有提供购买凭证，须人工补收 |
| summary_zh | string | 中文业务摘要，属于整理后的辅助信息 |
| category_id | string/null | 人工确认分类；新建或待复核时可能未确认 |
| priority | enum/null | 已分级的P0/P1/P2/P3；新建可为空；SLA另保留演示计时分级 |
| status | enum | 见后文13种状态 |
| assigned_team_id / assigned_agent_id | string/null | 已确认负责团队和人员；建议团队只在ai_suggestions中 |
| missing_fields | string[] | 尚需补收的信息；安全场景缺失项不阻塞升级 |
| related_ticket_ids | string[] | 历史关联，不意味着应合并 |
| duplicate_of_ticket_id | string/null | 人工确认合并到的原工单；只有merged状态使用 |
| safety_flag | enum | reported_risk / no_risk_reported；后者不等于经检测证明安全 |
| warranty_status | enum | 此版均为pending_manual_review，不自动批准或拒保 |
| tags | string[] | 展示/筛选标签，含场景信息；不能用于无泄漏分诊评测输入 |
| sla | object | 固定演示时钟下的当前计时周期及历史周期 |
| quality | object | 合成方式及根因是否确认；此版无真实根因认定 |
| source_context_ids | string[] | 对应research/sources.json，只证明背景来源，不证明本工单真实存在 |

### 状态

| 值 | 中文 | 用途 |
| --- | --- | --- |
| new | 新建 | 尚未完成建议与人工复核 |
| awaiting_review | 待人工复核 | AI建议待确认或情况不明确 |
| waiting_customer | 待客户补充 | 缺资料，保留追问和后续入口 |
| assigned | 已分派 | 有人工确认的团队与人员 |
| in_progress | 处理中 | 由负责团队推进 |
| waiting_parts | 待备件 | 关联备件申请，不能自动当作已发货 |
| waiting_visit | 待上门 | 关联预约提案，尚待确认 |
| escalated | 已升级 | 安全或需更高层人工处理 |
| resolved | 已解决待确认 | 记录恢复反馈，尚未关闭 |
| closed | 已关闭 | 人工确认关闭，保留完整历史 |
| cancelled | 已取消 | 排除当前SLA统计 |
| merged | 已合并 | 指向原单，保留原始来件 |
| reopened | 重新打开 | 开启新计时周期，保存旧周期结果 |

### SLA子对象

`policy_id`引用演示规则；`applied_priority`是计时使用的演示分级，非AI预测。`clock_start_at`是当前周期起点；`cycle`通常为1，重开为2。`first_response_due_at`、`resolution_due_at`为绝对目标时间。`first_response_at`是第一条客户可见人工回复时间；`resolved_at`是该周期解决时间。`first_response_breached`和`resolution_breached`保留已发生的历史超时，不能只凭当前是否待处理判断。`excluded`表示取消/合并等不参加SLA统计。`previous_cycle`在重开时保存旧周期结果。`as_of`为固定演示时刻。

P0为安全紧急；P1为高优先级故障；P2为一般故障；P3为普通咨询或低影响问题。具体时限是演示值，见规则文件，不是沃太承诺。

## 2. 主数据 reference/

| 文件 | 重要字段 | 关系与用途 |
| --- | --- | --- |
| products.json | model、segment、nominal_power_kw、nominal_capacity_kwh、source_ids | 公开产品参考；未核实的功率或容量为null |
| regions.json | country_zh、default_language、timezone、service_area | 演示国家与IANA时区，不代表官方服务版图或排班 |
| customers.json | type、tenant_id、preferred_language、preferred_contact、consent_to_service_contact | owner/installer/distributor/project_operator；联系方式均虚构 |
| sites.json | customer_id、installer_customer_id、country_code、timezone、segment | 一个客户可有多个站点；此版每站点一台演示设备 |
| devices.json | serial_number、product_id、site_id、customer_id、installed_on、firmware_version | 固件前缀demo-fw；安装日期亦虚构 |
| teams.json | country_codes、skills、languages、supported_segments、requires_human_assignment_approval | 国家为*代表全球演示组 |
| agents.json | team_id、skills、languages、availability、capacity、current_open_ticket_count | 专员快照；在线、忙碌、离线、休假；负载从当前工单重算 |
| categories.json | required_skill、required_intake_fields、unknown_code_policy | 分类依据是演示业务规则 |
| sla_policies.json | priorities、calendar、clock_start、pause_statuses | 连续UTC计时，不按当地工作日暂停 |
| routing_rules.json | precedence、rules、confidence_threshold、fallback等 | 建议路由；最终分派仍需人工确认 |
| workflow.json | statuses、transitions、actions_requiring_approval | 状态和人机协作边界 |
| roles.json | can、cannot | 本地Demo权限建议，开发仍需服务端落实 |
| knowledge_base.json | content_type、source_ids、content_zh、recommended_actions_zh | public_source_summary/demo_business_rule/design_inference区分事实与假设 |
| spares.json | compatible_product_ids、available_quantity、replenishment_eta | 演示备件类别，无真实料号或替代料建议 |

`segment`可为residential、commercial、utility、ev_charger、balcony。产品类别和路由技能不是同一维度。`warranty_status=pending_manual_review`不能拿来给客户承诺保内处理。

## 3. 工单子表 seed/

| 文件 | 主要字段 | 说明 |
| --- | --- | --- |
| messages.json | ticket_id、at、sender_type、sender_id、language、body、body_zh、visibility、attachment_ids | 原语言正文与中文辅助文本分开；internal不得直接对客户公开 |
| events.json | ticket_id、at、from_status、to_status、actor_type、actor_id、correlation_id | 可重放状态；人工动作有操作者ID |
| assignments.json | ticket_id、team_id、assignee_id、assigned_at、approved_by | 已确认派工的历史，不等于AI建议 |
| ai_suggestions.json | ticket_id、generated_at、proposal、review | 预设建议；review.status为pending/accepted/corrected；不是实时模型调用结果 |
| attachments.json | ticket_id、message_id、mime_type、relative_path、availability、kind | 路径相对data目录；正常附件是可读取的本地文本 |
| telemetry.json | ticket_id、device_id、sampled_at、fields、source | 只读合成快照；SOC为模拟值，不能诊断真实故障 |
| notifications.json | ticket_id、type、created_at、recipient_team_id、dedupe_key | 本地提醒；不会发出真实通知 |
| duplicate_candidates.json | ticket_id、candidate_ticket_id、match_reasons、decision、approved_by | 人工确认的跨渠道重复来件 |
| part_requests.json | ticket_id、part_id、quantity、status、approved_by | 缺货/待确认，不代表真实发货 |
| visits.json | ticket_id、site_id、proposed_start、timezone、status | 未来上门提案，不是已发生事件 |
| rma_requests.json | ticket_id、status、decision、approved_by | 退换申请草稿；未批准 |
| csat.json | ticket_id、customer_id、score_1_to_5、submitted_at | 虚构满意度，不能用作公司口碑证据 |

AI建议中的`proposal.confidence`为人为设定的0—1分数。`proposal.evidence_spans`是对应客户原文中的片段。`review.final_category_id/final_team_id`是人工复核结果；`corrected`案例用于展示“人可以不同意AI”，不表示真实模型出错率。

## 4. 评估与测试

| 文件 | 主键/结构 | 使用方法 |
| --- | --- | --- |
| evaluation/inputs.jsonl | id=CASE-xxxx | 每行一个单轮分诊输入，无最终答案字段 |
| evaluation/expected.jsonl | id与输入相同，expected为预期 | scenario_family_id用于分组；seed_ticket_id仅供调试跳转 |
| evaluation/example_agent_outputs.jsonl | case_id指向输入 | 是结构样例；execution中的操作均为false |
| evaluation/splits.json | name=development/validation/test | 同一场景族不跨组；仍可能共享基础文案 |
| evaluation/conversation_cases.json | id=CONV-xxx | turns为原始对话；checkpoints按第几次客户来件检查 |
| fixtures/edge_cases.json | id=EDGE-xxx，kind标明测试类型 | input是测试请求或业务上下文；expected定义正确行为 |
| fixtures/attachment_failures.json | SIM-* | 有意不存在本地文件的损坏/缺失/OCR不清测试元数据 |

`expected.next_action`可为propose_assignment、request_information、human_review、escalate_to_human等；这表示建议采取的下一步，不是动作已经执行。`must_not`是测试中的禁止行为，需在应用或Agent输出评估中验证。`root_cause=unknown_requires_evidence`明确不把分类当作故障诊断。

## 5. 调研、清单与校验

`research/sources.json`提供来源ID、标题、发布机构、URL、访问日期、中文概述及用途。来源URL证明公开事实，不证明模拟记录。`research/competitors.json`分别保存observed（公开所见）和design_inference（设计推论）。

`manifest.json`记录固定时刻、版本、种子、实体数量与文件哈希；自身与validation_report不纳入自校验哈希，避免循环。`validation_report.json`记录校验范围、断言数量、错误和明确未验证事项。

本字典的中文说明优先帮助理解业务，实际解析应以JSON字段名为准，不能把中文显示标签当作数据库键。
