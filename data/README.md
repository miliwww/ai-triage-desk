# 沃太能源售后工单分诊与流转：模拟数据包

用于任务4的业务调研、后续PRD、可交互Demo与功能测试。版本1.0.0，核查日期2026-10-24。

**这是模拟数据，不是沃太生产数据。** 真实部分是可溯源的公司/产品/公开服务资料；客户、故障、员工、组织、库存、服务时限、评价及经营指标全部虚构。没有使用个人简历里的联系方式或其他个人信息。所有邮箱均为保留的`example.invalid`域名，设备SN以`DEMO-`开头。

## 先看这几份文件

1. `research/公开信息调研与业务假设.md`：了解公司、产品、服务流程、竞争对照和设计假设。
2. `demo/demo_scenarios.json`：13条可直接讲解的演示路径，带真实存在的模拟工单ID。
3. `seed/tickets.json`：492条可直接导入的工单；`reference/`提供客户、站点、设备、产品、团队等关联资料。
4. `docs/开发与测试接入.md`：开发如何读数据、跑回归、处理时钟与人工确认。
5. `validation_report.json`：本地校验结果；本报告不代表已测试真实AI或真实应用。

## 数据规模与覆盖

| 内容 | 规模/范围 |
| --- | --- |
| 工单 | 480条基础案例＋12条经人工确认的跨渠道重复来件，共492条 |
| 业务场景 | 48类“问题＋上下文”组合，各10条语言/产品/时间/状态变体 |
| 国家 | 德国、荷兰、西班牙、英国、澳大利亚、中国、法国、意大利；仅演示分组，不是实际业务占比 |
| 语言 | 中文、英文、德语、荷兰语、西班牙语、法语、意大利语 |
| 产品参考 | 12款公开产品参考；不意味着每款在各模拟国家均获准销售 |
| 客户与设备 | 96个虚构客户、192个虚构站点、192台虚构设备 |
| 服务组织 | 27个虚构团队、54名虚构专员，含区域技能、人员可用性与容量 |
| 分类与状态 | 14个问题类别、13种工单状态、4档演示优先级 |
| 分诊输入与预期 | 480组输入、独立预期结果和示例输出 |
| 边界测试 | 76例，覆盖业务理解、输入校验、权限、流转、资源不足和SLA秒级边界 |
| 连续对话 | 24组多轮检查点，用于补充资料、授权和新风险处理 |
| 附件 | 本地文本附件可用于上传/关联测试；损坏、缺失和低置信度OCR另有元数据夹具 |

这些场景是有意构造的覆盖样本，不是统计抽样。相似基础文案有重复，适合功能回归、提示词调试和演示，不宜作为真实泛化准确率或故障频率依据。

## 给开发者的最短接入方法

读取`seed/tickets.json`作为列表。按照ID关联`reference/customers.json`、`sites.json`、`devices.json`和`products.json`；工单详情再按`ticket_id`读取`messages.json`、`events.json`、`assignments.json`等子表。**ID是关联键，不能使用数组下标连接。**

模拟AI演示可读取`seed/ai_suggestions.json`并明确显示“预设演示建议”。真正调用模型时，输入来自`evaluation/inputs.jsonl`，相关主数据必须经权限过滤；不把`expected.jsonl`、完整工单后续结果或示例输出传给模型。

所有时间是UTC、RFC3339字符串。演示时钟固定为`2026-10-24T04:00:00Z`（北京时间2026-10-24 12:00），不要用电脑今天的时间计算静态种子数据的超时。站点另有IANA时区，供展示转换。

## 再生成与校验

在`data`目录用Python 3.10或以上运行，无第三方依赖：

```powershell
python scripts/build_dataset.py
python scripts/validate_dataset.py
```

运行前请复制你已编辑的种子文件；生成脚本会覆盖本包的同名生成文件。生成规则和随机种子固定，便于复现；Markdown说明文件不由生成器覆盖。生成器不联网、不调用真实客服、不发送通知，也不控制设备。

若命令行没有`python`，可把命令中的`python`换成环境中可用的Python解释器完整路径。校验成功返回退出码0，失败返回1并输出问题位置。

## 使用边界

- JSON采用UTF-8无BOM；JSONL每行一个对象；`null`表示未知/未核实，不应当成空字符串或数值0。
- `is_synthetic: true`表示整条业务记录虚构；产品主数据的真实字段另有来源说明。
- 所有P0—P3、团队和时限是演示规则，不是官方承诺。未知故障码不提供部件损坏结论。
- 本包的待上门时间是未来预约提案，不能当作已确认或已发生事件。
- 本地附件为文本，不能用来证明照片识别、OCR或视频能力。故障附件元数据中的文件缺失是刻意测试场景。
- 当前交付是调研与数据包，未实现PRD、前端、后端或真实Agent；`api_examples.json`是开发契约建议。
