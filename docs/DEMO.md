# 两分钟演示与讲解

准备：打开首页，确认中文；首次演示可点击两次“重置演示数据”。全程使用模拟数据和预设分诊建议，演示时不必背诵工单编号。

## 讲稿

**约 20 秒，问题与入口**

这是我在公司 AI 黑客松培训中，使用 Codex 与 Kimi Code CLI 完成并进一步打磨的售后工单流程原型。它面向海外储能售后场景，重点是把多语言反馈整理成可跟进的任务，明确哪些步骤由人确认。首页提供普通服务和风险处理两个案例。

**约 35 秒，建议与复核**

先看西班牙客户反馈：停电时备用照明没有生效。这里保留客户原文和证据，给出类别、优先级和团队建议。本版使用预设建议，主要验证工作流。人工可以确认，也可以修改；修改关键结论需要说明原因，原始建议和更正记录都保留。

**约 25 秒，派工与结案**

确认建议后，选择可用人员。离线、忙碌或容量已满的人员不能接受新派工。确认后负责人和记录同步更新。处理完成也不能直接关闭，需要先记录结果，再补客户确认依据。

**约 25 秒，风险接管**

再看暴雨积水风险。工单已经升级、有人回复，都不代表真正接管。应急人员要单独填写接管说明和下次更新时间；缓解也要记录依据。风险未缓解时，系统会阻止直接解决或关闭。

**约 15 秒，实现与边界**

前端采用 Angular 与 Signals，业务动作在 Store 中校验，页面按状态显示下一步。当前补充了 18 项应用测试，并整理了数据校验与静态交付流程。真实模型和受控工具调用是下一阶段的扩展。

## 实际点击顺序

普通服务：首页“体验分诊流程” → 确认原建议 → 选择演示专员013 → 确认派工 → 处理与结案 → 开始处理 → 填写结果和依据 → 标记解决 → 填写客户确认依据 → 关闭。

风险案例：首页风险案例 → 点击“确认接管”指引 → 填写接管说明 → 确认人工接管 → 填写缓解依据 → 记录风险缓解。

两分钟展示时可以只讲结案规则，完整点击链路留到追问环节。页面刷新会恢复初始数据，因此演示中尽量使用工作台导航。

## 常见追问

**这是不是一个真实 Agent？**

目前是 AI 分诊与人工协同的交互流程原型，建议源是模拟数据和演示规则。它具备人工确认与记录机制，但没有真实模型循环和工具执行。

**代码是怎样完成的？**

初版使用 Codex 生成 PRD 和模拟数据，使用 Kimi Code CLI 拆解任务并实现代码；本轮继续使用 Codex 做视觉、交互、验证与交付。介绍本人工作时对应真实过程，不把工具生成的代码说成本人全部手写。

**接模型后如何验证？**

先定义输入和结构化建议契约，服务端调用模型，验证输出后进入人工复核。使用独立预期评估类别、路由、缺失字段与风险处理，隔离答案，并记录失败案例、延迟和调用成本。当前数据是构造样本，需要披露局限。
