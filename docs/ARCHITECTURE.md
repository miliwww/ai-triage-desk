# 实现说明

本文件描述 v0.1.0 的实际实现。项目是浏览器内存态原型，分诊建议由种子数据或演示规则提供。

## 从输入到服务记录

1. `DataService` 并发读取 20 份 JSON 资源。同一轮加载共享 Promise，成功后复用结果，失败后清除进行中的 Promise，允许重试。
2. `Store.init()` 设置响应式主数据和各业务数组，页面按 ID 关联客户、站点、设备、产品与团队。
3. 页面从 `views`、`viewsById`、`stats`、`currentRisks` 等派生状态读取展示数据。
4. 人工操作调用 Store 动作。动作先校验，再更新工单、分诊复核、分派、事件或消息记录。
5. `computed` 根据依赖重新计算视图，徽标、指标和流程指引随之更新。

## 两类状态需要区分

普通服务链路：分诊建议 → 人工复核 → 确认派工 → 处理 → 已解决待确认 → 客户确认关闭。

风险记录链路：`queued` → `taken_over` → `mitigated`。

风险记录与工单状态分开保存。进入风险队列不代表已接管，缓解不代表设备已修复；仍有未缓解风险时，解决和关闭动作会被拦截。现有内部 `awaiting_review` 状态包含复核到派工前的阶段，页面另用建议复核记录和 `pendingDispatch` 区分待派工队列。

## 一条复核记录包含什么

```text
原始建议：类别、优先级、团队、缺失字段、原文证据、演示知识条目
人工决定：接受 / 更正、最终类别、最终团队、说明、操作者、时间
工单结果：更新后的类别、优先级与缺失字段
追溯：内部复核消息与 ai_review_confirmed 事件
```

更正关键字段时需要原因。原建议的类别、优先级和团队继续保留；复核选定的缺失字段用于后续信息收集。示例分数来自预设数据，不是模型运行结果。

## SLA 与时钟

- 基准时钟固定为 `2026-10-24T04:00:00Z`，以北京时间显示。
- 严格超过到期时间才判定超时；恰好到期不算。
- 内部备注不计首响，客户可见人工回复才会记录首响。
- 重开建立新周期，旧周期的响应、解决和超时记录保留。
- P0 的演示目标是人工应急接管目标示意，不是设备修复承诺。

## 运行数据与评估材料

网页构建只复制 `data/seed/*.json`、`data/reference/*.json`、`data/demo/dashboard_expected.json`。源码保留完整数据研究、生成脚本、Schema 与独立评估材料，便于复现和审查。

本版不把 `evaluation/expected.jsonl` 部署为网页资源，也没有向真实模型发送任何数据。

`scripts/eval_rule_baseline.py` 是一个不调用模型的规则基线：它在开发集上拟合关键词画像，验证集检查一次，测试集只报一次，并生成 [评估报告](EVALUATION.md)。它同时用来确认标注口径——给定类别后，优先级、团队、缺失字段与升级标记都能由 `reference/` 规则和入参完整度复现（480/480），因此这套评测实际只衡量类别判定。

模型评估仍是未来工作：需按场景族划分样本，隔离预期答案，记录模型和提示词版本、实际输出、延迟、成本、错误分类与人工更正情况。规则基线可作为对照下限。

## 后续真实 AI 接入点

这是扩展建议，尚未实现：

1. 将 `presetSuggestion` 的建议来源抽象为可替换服务；预设模式继续支持离线演示。
2. 服务端接收授权范围内的工单原文和必要主数据，执行模型调用，校验结构化输出。
3. 建议只写入待复核记录，模型不直接修改负责人、关闭工单或发出设备控制命令。
4. 超时、结构错误和证据不足时展示可解释失败，保留人工处理入口。
5. 使用独立预期进行离线评估，报告构造样本的适用范围，避免把种子表现当成真实业务准确率。

## 本轮视觉原则

深蓝导航 `#18374b`、浅色画布 `#f3f6f9`、行动蓝 `#1765d8`、协同青 `#137b79`、风险红 `#b91c1c`。首页的流程图与案例入口承担展示重点，其余页面优先保证信息层级、操作清晰和可读性。

使用系统字体，不依赖远程字体或图片服务。新增图形采用内联 SVG；主导航、表单与按钮有键盘焦点，窄屏提供独立导航。
